LIBS Control Application

Royal Belgian Institute of Natural Sciences · 2026

A desktop application for controlling and managing LIBS (Laser-Induced Breakdown Spectroscopy) hardware — integrating a pulsed Viron laser, GRBL CNC sample stage, Avantes spectrometers, and Basler microscope camera into a single interface for both one-shot acquisition and fully automated 2-D elemental mapping.

Key capabilities

  • One-shot & multi-shot (profile) spectrum acquisition with real-time plotting
  • Dark correction, peak detection & elemental identification
  • Live microscope view with crosshair overlay and image capture
  • Manual XYZ stage positioning via GRBL-controlled CNC
  • Automated 2-D raster mapping with compressed NetCDF output
  • Automatic laser fault recovery during long mapping runs
  • Live progress preview images (with optional FTP upload)
  • Persistent JSON configuration with per-session settings

Launching the Application

Double-click launch_LIBS.bat or run python Bruniquel_LIBS_improved.py from the command line. The splash screen appears while the environment initialises — paths, DLLs, logging, and hardware detection all happen automatically.

First run: A default config.json is written next to the application script. Edit it to match your serial ports, laser IP, and preferred defaults.

Window Layout

The window is divided into three resizable columns using splitters. Drag the borders between columns to adjust proportions.

Column Content
Left Main tab widget — Acquisition, Mapping, Peak ID, Settings
Center Manual Controls — directional XYZ stage buttons and step-size selectors
Right (upper) Microscope live view tab
Right (lower) Application Console log
Tip: Column sizes are remembered between sessions. Resize them once and they will be restored on next launch.

Acquisition Tab

The primary workspace for one-shot and profile (multi-shot) spectrum acquisition.

Laser Controls

Control Description
Connect Laser Opens TCP connection to the Viron laser, logs in, waits for ready, sends $STANDBY then $FIRE. A progress bar shows warm-up progress.
Stop Laser Sends $STOP and optionally closes the connection. Safe to press at any time (non-mapping mode).
External Laser Checkbox — enables external-trigger mode. The laser fires only on an external electrical trigger instead of its internal oscillator.

Output Settings

Control Description
Save directory Where CSV files are written. Use Browse… or type directly. Synchronized with the Mapping tab.

Single-Shot Acquisition

  1. Connect the laser and wait for the progress bar to complete.
  2. Set integration time, trigger delay, and output directory.
  3. Press Go (One Shot). The spectrometer arms, triggers, captures, dark-corrects, and plots the result.
  4. The spectrum is automatically saved as CSV.

Profile Acquisition

Fires multiple consecutive shots at the same position. Configure Profile Steps (5–50 shots) and Shots Delay (0–20 s). Press Go (Profile). Each shot is plotted in a stacked overlay view and saved to a multi-column CSV.

Detect Peaks

Press Detect Peaks to overlay detected peaks on the spectrum plot (identified by prominence). For full element identification, switch to the Peak ID tab.

Microscope Tab

Displays a live feed from a Basler camera (via pypylon) with a green crosshair overlay centered on the field of view. The image auto-scales to fill the available space.

Control Description
Save Capture Saves the current frame as PNG in the output directory.
Microscope Light Toggles the LED ring light on/off via the Arduino serial connection.
Note: If pypylon is not installed, the camera panel remains blank but all other features continue to work. During mapping, the camera is automatically paused and resumed afterward.

Peak ID Tab

Automated peak detection and matching against a built-in reference line database covering common LIBS elements.

Workflow

  1. Acquire a spectrum or load a saved CSV via Load Spectrum.
  2. Adjust Min Height and Min Prominence thresholds.
  3. Press Run Peak ID.
  4. Peaks are highlighted on the plot; a results table shows each match.
  5. An element summary card lists all identified elements.

Mapping Tab

Orchestrates fully automated 2-D raster scans. The sample is moved line-by-line under the laser while spectra are collected at each point and written to a compressed NetCDF file.

Int. delay (ns) Delay between trigger and integration start

Mapping Controls

Button Action
Start Mapping Validates all devices are connected, then starts the background mapping thread. Camera and microscope light are automatically paused.
Stop Mapping Requests a graceful stop after the current scan line completes. The NetCDF file is properly closed with all data collected so far.

Progress Preview & Estimates

A live progress image appears in the mapping tab, showing the element intensity distribution built up line-by-line. Before starting, the application shows estimated mapping duration and output file size based on your parameters — these update in real-time as you change settings.

Settings Tab

Consolidates application-wide configuration:

  • Spectrometer Selection — lists detected Avantes spectrometers with serial numbers and wavelength ranges. Check/uncheck to enable or disable individual units.
  • Connection Status — shows live connection state of all hardware devices (CNC, pulse controller, laser, spectrometers).
  • Mapping Parameters — basic and advanced mapping forms embedded for editing without switching tabs.
  • Integration Time & Trigger Delay — wheel-style selectors for spectrometer acquisition timing.

Application Console

The console panel at the bottom-right streams log messages in real time. All messages are also written to timestamped files in the logs/ directory. During mapping, the console shows per-line acquisition progress, pulse controller counts, and any warnings or error recovery actions.

Avantes Spectrometers

The application auto-discovers all connected AvaSpec spectrometers via USB using the avaspecx64.dll driver. Multiple spectrometers are sorted by wavelength range and fused into a single broadband spectrum.

Setup

  • Connect spectrometers via USB. The DLL must be in the application directory.
  • At startup, spectrometers are detected automatically. Press Detect Spectrometers in Settings to re-scan.
  • Check/uncheck devices to select which to use for acquisition and mapping.

Key Parameters

Parameter Description
Integration time How long the sensor collects light per shot (ms)
Trigger delay Delay after trigger before integration starts (ns, FPGA ticks at 48 MHz)
Averages Number of scans averaged per measurement point
Trigger mode External (hardware trigger) or software trigger
Note: During long mapping runs, spectrometers are automatically re-initialized every 50 lines (configurable) to prevent DLL/USB state drift. "Spectrometer re-sync" messages in the console are normal and expected.

Viron Laser

The Viron pulsed laser is controlled over a raw TCP socket (Telnet protocol, port 23). All commands are paced with a minimum 1-second gap to satisfy the laser's CAN bus timing requirements.

Connection

Parameter Default Config key
IP address 192.168.103.103 laser.host
Port 23 laser.port
Login code (see config.json) laser.login_code
Timeout 60 s laser.timeout

Laser Lifecycle

OFF → LOGIN → STANDBY → READY → FIRE → (firing) → STOP

The application handles the full lifecycle automatically. During mapping, the laser stays in FIRE mode for the entire run — no commands are sent between scan lines.

Safety: Always wear appropriate laser safety eyewear. The Stop Laser button immediately sends $STOP. Use Emergency Stop on the CNC panel to halt all motion.

CNC Table (GRBL)

The sample stage uses a GRBL-controlled CNC system communicating over serial. It provides XY horizontal movement and Z vertical (focus) adjustment.

Parameter Default Config key
Port COM8 serial.cnc_port
Baud rate 115200 serial.cnc_baudrate

All movements use GRBL jog commands ($J=G91 …) for real-time motion. During mapping, the X axis moves continuously while the Y axis steps between lines.

Important: The steps_per_mm setting (default 800) must match your CNC controller's $100/$101/$102 GRBL parameters. An incorrect value will produce wrongly scaled maps.

Pulse Controller

An Arduino-based pulse controller bridges CNC motor step signals and the laser/spectrometer triggers. It counts CNC step pulses and emits a trigger every N steps, synchronizing laser shots to exact spatial positions.

Parameter Default Config key
Port COM3 serial.pulse_port
Baud rate 115200 serial.pulse_baudrate

Commands

Command Function
STEP n Set trigger interval to every n CNC steps
START Arm the controller and begin counting
STOP Stop triggering immediately
RESETCOUNT Reset the emitted-trigger counter
COUNT Read the current trigger counter value

Basler Camera

A Basler industrial camera (via pypylon SDK) provides the microscope live view. The image is cropped, scaled, and overlaid with a green crosshair centered on the ablation point.

Parameter Default Config key
Image size 1920 × 1080 camera.micro_img_size
Display scale 2× camera.disp_scale
Crop region [100, 980, 300, 1620] camera.crop_region
Crosshair lines Enabled camera.crosshair_lines

Mapping Workflow

Pre-flight Checklist

  1. Connect all hardware: CNC, pulse controller, laser, spectrometers.
  2. Position the sample under the laser using manual controls & microscope.
  3. Set mapping parameters (X/Y size, step size, laser frequency).
  4. Verify the estimated duration and file size shown below the forms.
  5. Press Start Mapping.

Automated Sequence

  1. Validation — all four devices checked (CNC, pulse, laser, spectrometers).
  2. Camera & light pause — camera feed stops, microscope LED turns off.
  3. Laser configuration — external-trigger mapping mode applied.
  4. Dark capture — dark spectrum acquired (no laser, software trigger).
  5. NetCDF creation — output file created with metadata.
  6. First line — $STANDBY → wait_ready → $FIRE, then scan.
  7. Lines 1..N — no laser commands; hardware trigger chain runs autonomously.
  8. Progress images — updated every N lines.
  9. Cleanup — laser stopped, NetCDF closed, camera & light restored.

Scan Line Phases

Phase What happens
1. Arm Configure spectrometers for callback-mode acquisition (x_points scans), arm pulse controller (STEP n + START), send CNC forward jog with margin.
2. Collect For each X point, block on spectrometer callback queue — dark-correct, merge across devices, write to NetCDF.
3. Cleanup Stop triggers, wait for CNC idle, read pulse count, return carriage to start, flush NetCDF to disk.

Hardware Trigger Chain

During CNC movement, the trigger chain runs autonomously — the software does not control shot timing:

CNC stepper motor ──step pulses──→ Pulse controller ──(every N steps)──→ Trigger out │ ┌──────────────────┤ ▼ ▼ Laser fires Spectrometers (ext. trigger) start integration │ │ ▼ ▼ Plasma emission → Spectrum captured

The software arms everything, starts the CNC motion, and collects results as fast as they arrive via DLL callbacks (no polling).

Fault Recovery

If a laser fault occurs (spectrometer timeout or pulse count mismatch), the system automatically recovers:

  1. $STOP — take laser out of FIRE mode.
  2. Wait 30 seconds for laser to settle.
  3. Reconfigure for mapping ($TRIG EI, $BURST 0, $QSPRE 1, $QSON 1).
  4. $STANDBY → wait_ready → $FIRE.
  5. Re-initialize spectrometers.
  6. Retry the failed scan line (up to 3 attempts per line).

Configurable Parameters

Parameter Default Description
shot_timeout_s 30.0 Seconds to wait for a single spectrometer callback before timeout
max_line_retries 3 Maximum retry attempts per line before aborting
line_start_wait_s 5.0 Seconds to wait after $FIRE before scanning
resync_every_n_lines 50 Perform full spectrometer re-init every N lines (0 = disabled)
Abort conditions: Mapping aborts if the same line fails after the maximum retries, or if the user presses Stop Mapping. In both cases, all data collected so far is safely saved in the NetCDF file.

All settings are stored in config.json next to the application script. Created automatically on first launch, updated when you change settings through the UI.

Troubleshooting

Problem Likely Cause Solution
No spectrometers detected USB not connected or DLL missing Check USB cables. Verify avaspecx64.dll is in the app directory. Press Detect Spectrometers.
Laser won't connect Wrong IP or laser not powered Verify laser IP in config.json. Check network cable and power. Try pinging the IP.
CNC not responding Wrong COM port or GRBL not ready Check COM port in Device Manager. Power cycle the CNC controller. Verify baud rate (115200).
Pulse handshake fails Wrong COM port or firmware Check COM port. Ensure Arduino runs the correct firmware. Try power cycling.
Camera preview black pypylon not installed or camera offline Install pypylon. Check USB3 connection. Verify with Pylon Viewer.
ShotTimeoutError Laser fault or trigger chain issue Auto-recovery runs (up to 3 retries). If persistent, check laser status, trigger cables, pulse controller.
Re-sync messages Normal periodic maintenance Expected every 50 lines. DLL is re-initialized to prevent USB drift. No action needed.
Wrong map scale Incorrect steps_per_mm Verify steps_per_mm matches your GRBL $100 setting.
App won't close during mapping Background thread running Press Stop Mapping first. Wait for the current line to finish.

Tips & Best Practices

General

  • The app starts maximized. Drag splitters between columns to resize; positions are saved between sessions.
  • Hover over any control for a tooltip with a brief description.
  • Use Load Spectrum in Peak ID to re-analyze previously saved CSV files.
  • Dark correction is automatic before each acquisition and at the start of each mapping run.

Mapping

  • Always perform a single-shot test before mapping to verify spectrometer alignment and laser focus.
  • Use the microscope to confirm the laser ablation spot location.
  • Set the progress element to a dominant element in your sample for the best preview.
  • For high-resolution maps (small step size), verify the estimated file size fits on your storage.
  • The FTP upload feature lets you monitor mapping progress remotely.

Maintenance

  • Keep the logs/ directory periodically cleaned to avoid accumulating many small files.
  • Back up config.json before making large changes.
